## Common object

Every transaction references frozen inputs for five typed layers and
carries the two subject records the binding stage compares:

```text
policy
evidence
runtime-state attestation_result object
authority/action/effect path
measurement support
canonical_action      (policy-owned effect + profile, authority-owned
                       resource, operation, terminal scope and window)
observed_effect       (evidence-owned effect, resource, issued_at;
                       measurement-owned profile identity)
```

The strict verdict is non-compensable, and since v3 it also requires that
the five predicates speak about the same subject:

```text
ALLOW iff policy ∧ evidence ∧ state ∧ authority ∧ measurement ∧ binding
```

`binding` is not a sixth artefact predicate. No sixth artefact and no sixth
verifier is introduced. It is a well-formedness condition on the
conjunction itself, evaluated over subject fields that the five verifiers
already inspect. `failed_layers` therefore stays a list over the five
artefact layers, and a transaction with `failed_layers == []` and
`verdict == "DENY"` is exactly a **cross-layer denial**.

## What changed vs v1 and v2, and why (review blockers B1–B5)

**B1 — one composition rule, declared label provenance.** In v1 the
five-layer precedence ladder existed as three same-author transcriptions
(`build_corpus.py`, `verify_transactions.py`, `oracle.sql`), so the
headline agreement could only fail if one transcription diverged from the
others. v2 moved the conjunction and the first-rejecting-gate ladder into
the single shared module `composition_rule.py`, imported by BOTH the corpus
builder and the verifier; v3 keeps that module the only Python home of the
binding stage and the subject-derivation functions as well. The consequence
is stated in `corpus.json` and in every generated summary
(`label_provenance`): expected labels are generated by `build_corpus.py`
using the same composition rule module the verifier imports; **composition-
level agreement is analytic; the substantive check is per-layer agreement;
labels are not externally independent.**

**B2 — the state layer is appraised, not declared.** v1 carried a bare
`runtime_state` string compared to `"affirming"` inline. v2 transactions
embed `attestation_result` objects (patterns from `state-fixtures.json`)
and the verifier calls `state_adapter.appraise_state` at the fixed
`state_decision_time` — a structural appraisal with a status gate, an
inclusive freshness window and a reference-digest comparison, emitting
`PASS` / `CONTRAINDICATED` / `STALE` / `REFERENCE_MISMATCH`. This is a
structural field comparison of corpus-supplied objects; it is **not**
cryptographic attestation of any runtime (the disclaimer travels inside
every `details` dict).

**B3 — the co-failure matrix is filled.** The v1 corpus was
block-diagonal: authority×policy, authority×evidence, state×policy and
state×evidence co-failures were all **zero**. v2 added the
`cross_layer_joins` family so that the 5×5 pairwise co-failure matrix has
**no zero off-diagonal cell** (minimum off-diagonal count corpus-wide: 5).
22 of the 31 possible non-empty failure subsets occur (**v1: 13**; the v2
README said 14, which was wrong — the v1 verdict file contains 13 distinct
non-empty failure subsets).

**B4 — stratified reporting.** `summary.json` reports per-family baseline
false allows, the failure-set distribution, the full co-failure matrix,
coverage tables and an `analytic_identities` object.

**B5 — the composition seam is now implemented, not asserted.** This is the
v3 rebuild, and it is the substantive one.

*The defect.* The article's motivating counterexample in section 1 reads:
"an evidence receipt can correctly describe a WRITE effect when the valid
delegation path permits only READ". The v2 composed verifier **allowed**
that transaction. Four causes, all in the artifact:

1. `evaluate_evidence` checks only signature validity and nonce replay. It
   never compares `evidence.effect` to anything. (This is still true — the
   fix is at the join, not in the layer.)
2. `required_effect` and `required_measurement_profile` were written into
   the signed policy by the policy laboratory's corpus builder and read by
   **no evaluator anywhere**. They were inert payload bytes whose only
   function was to change the object digest.
3. `composition_rule.compose()` took six scalar strings with no cross-layer
   argument, so no transaction could exist in which all five layers pass
   individually and the composition denies. The v2 `cross_layer_joins`
   family was not a join: each transaction was a 4-tuple of independent
   fixture identifiers with two independent faults set at once.
4. `canonical_action` and `observed_effect`, advertised by section 4 of the
   article as fields of the decision transaction, did not exist anywhere in
   the artifact.

*The fix.* `compose()` gains a `subjects` argument; a pure function
`bind(subjects)` runs over the two subject records and returns a typed
outcome; the first-rejecting-gate ladder gains a final binding stage.
`canonical_action` and `observed_effect` are now real transaction fields,
built by `composition_rule.subjects_of` and **re-derived and checked** by
the verifier (`subject_matches` in `summary.json`), so section 4 describes
the artifact that exists. `required_effect` and
`required_measurement_profile` are the policy-owned half of
`canonical_action` and are therefore load-bearing.

*Why the binding stage lives in the composition rule and not in a layer.*
`required_effect` is owned by the policy artefact; `effect` / `resource` /
`issued_at` by the evidence artefact; the terminal narrowed scope and the
delegation window by the authority artefact; the profile identifier by the
measurement artefact. A predicate over all four has no local home. Putting
it inside `evaluate_evidence` would make the evidence column of the
co-failure matrix partly a copy of the policy column and could not express
the resource, time or profile mismatches at all. Putting it inside the
authority evaluator would be cross-layer analysis wearing a single-layer
costume, would make the composition rule vacuous (every denial would again
be "a layer failed"), and would force a rebuild of the frozen 16-case
delegation suite and its SQL oracle. **Neither sibling laboratory is
modified by this rebuild**: their evaluators are imported and executed as
shipped, which is the strongest practical evidence that the seam really is
located in the join.

*Consequence for the article's model (section 1 must be amended).* The
sentence "A mismatch between the canonical action and the observed effect
therefore surfaces as an authority or evidence failure" is **false** and
must be deleted: neither layer can see both sides. It surfaces only at the
join. The replacement is a strengthening, not a retreat — the seam the
article names is architecturally located in the composition rule, which is
the paper's own contribution.

## The binding stage

Typed outcomes, in rule order (first failing rule wins):

| rule | outcome | gate |
| --- | --- | --- |
| 0 | any required subject field absent | `binding.undetermined` |
| 1 | observed effect ≠ policy `required_effect`, or not in the terminal granted tools | `binding.effect` |
| 2 | observed resource ≠ canonical resource, or not in the terminal granted resources | `binding.resource` |
| 3 | evidence `issued_at` outside the authorised window | `binding.time` |
| 4 | measurement `profile_id` ≠ policy `required_measurement_profile` | `binding.measurement_profile` |
| 5 | otherwise | `binding.verified` |

Two properties are deliberate.

- `bind` is **pure over the subjects** and is evaluated for every
  transaction independently of the five layer results. That is what lets
  the point-only ablation keep the binding stage while ablating only the
  measurement criterion.
- The ladder **consults** the binding result only after all five layers
  have passed. This is not fail-open: if a layer has failed the transaction
  is already DENY and the earlier gate is the honest localization. A
  missing subject field yields `UNDETERMINED`, which never counts as a
  pass. `binding.undetermined` is never the first rejecting gate in this
  corpus (all 11 UNDETERMINED transactions have a MISSING policy, which
  fires first).

The authorised window is the **intersection** of the per-edge validity
windows, and containment is tested, never equality. The artifact has three
unrelated time constants — policy/state decision time
`2026-07-25T21:30:00Z`, authority `effect_time` `2026-07-25T20:00:00Z`,
evidence `issued_at` `2026-07-25T21:29:30Z` — so there is no single
decision clock. That is a real limitation, reported here and not repaired.

**Honesty ceiling.** The binding stage is a deterministic string-agreement
and interval-containment condition over subject fields read out of
corpus-supplied artefacts. It verifies no signature, takes no measurement,
contacts no attestation service and proves nothing about any deployed
system. Denials it produces are denials on a designed corpus.

## Comparison baselines

Six author-defined ablations are evaluated on the identical 104
transactions. Three reproduce deliberately weak local-only strategies:
artifact-validity-only, point-estimate-only measurement, and a
four-of-five majority. Three are stronger, subject-aware partial joins:

| baseline | all five local verifiers | effect/resource | time | measurement profile |
| --- | ---: | ---: | ---: | ---: |
| `effect_resource_binding` | yes | yes | no | no |
| `effect_resource_time_binding` | yes | yes | yes | no |
| `effect_resource_profile_binding` | yes | yes | no | yes |

The partial joins are not claimed to represent named products. They are
schema ablations: each checks a useful subset of the subject record and
omits a different cross-layer coordinate. Their false allows localize the
marginal value of the omitted coordinate on this designed corpus.

### cross_layer_binding design rationale

Every transaction in the family is built so that all five artefact
verifiers pass: the unmodified correct signed policy, a correctly signed
evidence object with a fresh nonce, the affirming and fresh attestation
result, an ALLOW delegation path, and a measurement fixture its own
evaluator passes. The only thing that varies is subject agreement.

| transaction | varied subject | binding outcome |
| --- | --- | --- |
| `XLB_effect_write_two_hop` | effect `ledger.write` | `EFFECT_MISMATCH` |
| `XLB_effect_write_other_resource_two_hop` | effect `ledger.write` on `invoice-999` — the article's section-1 counterexample verbatim | `EFFECT_MISMATCH` |
| `XLB_effect_export_four_hop` | effect `ledger.export`, four hops | `EFFECT_MISMATCH` |
| `XLB_resource_other_two_hop` | resource `invoice-999` | `RESOURCE_MISMATCH` |
| `XLB_resource_other_one_hop` | resource `invoice-999`, one hop | `RESOURCE_MISMATCH` |
| `XLB_issued_after_window_two_hop` | `issued_at` 1 s after path expiry | `TIME_MISMATCH` |
| `XLB_issued_before_window_two_hop` | `issued_at` 1 s before path validity | `TIME_MISMATCH` |
| `XLB_measurement_profile_two_hop` | measurement profile the policy does not require | `PROFILE_MISMATCH` |
| `XLB_CONTROL_read_two_hop` | — (control) | `PASS` → ALLOW |
| `XLB_CONTROL_read_one_hop` | — (control) | `PASS` → ALLOW |
| `XLB_CONTROL_read_four_hop` | — (control) | `PASS` → ALLOW |
| `XLB_CONTROL_window_lower_two_hop` | `issued_at` on the inclusive lower boundary | `PASS` → ALLOW |
| `XLB_CONTROL_window_upper_two_hop` | `issued_at` on the inclusive upper boundary | `PASS` → ALLOW |
| `XLB_CONTROL_main_profile_two_hop` | required profile (control) | `PASS` → ALLOW |

Two constructions are **owned by this laboratory** and are not upstream
data. Both are disclosed in `corpus.json` with their own notes.

- `evidence_variants` — nine evidence objects signed with the policy
  laboratory's own test key and its own `sign_object` function (imported,
  not transcribed), each with a fresh nonce, each of which the
  **unmodified** evidence evaluator passes. They were necessary because the
  binding transactions cannot be built by varying the policy: any edit to a
  signed policy changes its digest, and `evaluate_policy` compares that
  digest against the anchor, so the policy layer would report `SUBSTITUTED`
  and the transaction would no longer be an all-layers-pass case.
- `measurement_variants` — two fixtures in the SAFE fixture schema,
  appraised by the **unmodified** v3 SAFE evaluator, which passes both.
  They differ only in profile identity. They were necessary because the
  shipped `measurement_profile_mismatch` fixture already fails its own
  layer, so it cannot produce an all-layers-pass profile disagreement.

Design constraints are enforced as deterministic assertions in
`build_corpus.py::check_design_constraints` (including: at least one
cross-layer denial exists; every cross-layer denial has an empty
`failed_layers` and a `binding.*` first gate; all four mismatch outcomes
and `PASS` occur in the family; at least four matched controls) and
re-checked at run time by the verifier's exit gate.

## Baselines

- artifact-validity/policy-presence only;
- point-only measurement gate;
- four-of-five compensating majority.

These are experimental ablations defined by the authors, not
representations of named external systems. False-allow counts are counts on
a designed corpus — corpus-coverage statistics, not rates.

Two notes on what each ablation now removes:

- **point-only** replaces *only* the measurement criterion and keeps the
  binding stage. One consequence must be reported rather than buried: its
  false-allow count on the 90 pre-existing transactions falls from 3 (v2)
  to 2, because `F_correct_good_profile_mismatch` — where the SAFE
  evaluator's `point_only_result` ignores the profile gate — is now caught
  by `binding.measurement_profile` instead. No other v2 number over those
  90 transactions changed.
- **four-of-five** votes over the five artefact verifiers only, so it is an
  ablation *of* the binding stage as well. All 8 cross-layer denials are
  false allows for it.

## Run

```bash
./run.sh
```

Entry points (all deterministic: fixed decision times, fixed seeds inside
the SAFE corpus, no wall-clock, no network): state-adapter self-test,
`build_corpus.py`, `test_cross_layer_binding.py` (the acceptance test for
the article's section-1 counterexample), `verify_transactions.py`,
`run_sql_oracle.py`, then checksum verification. Re-execution is
byte-identical (verified with two full `run.sh` runs on 2026-07-27:
identical stdout and identical result-file digests).

`results/` — 104/104 expected typed tuples, 104/104 per-layer agreement
(the substantive check), 104/104 subject-record agreement, 15 allows /
89 denies, of which **8 are cross-layer denials** (every artefact verifier
passed; the join refused). Composition-level agreement is analytic per B1.

`results-sql-oracle/` — 104/104 agreement with the Python composition and
with the expected labels, including 104/104 on the typed binding outcome.
In v3 the oracle no longer receives the binding outcome as an input: it
receives the subject strings and **re-derives** the outcome in SQL, so
SQL/Python divergence in the binding rules is detectable. It still consumes
per-layer results produced by the Python evaluator, reimplements no
signature, bootstrap, delegation-path or state appraisal, and is **not
independent validation** — it is a transcription check between two
same-author implementations.

`result-2026-07-25.md` records the v1 (56-transaction) run,
`result-2026-07-27.md` the v2 (90-transaction) run; both are retained as
historical records of superseded corpora. `result-2026-07-27-v3.md` records
this run.

## Claim ceiling

This is a frozen synthetic/hybrid benchmark composition. All expected
labels are author-written programme-internal expectations, not external
ground truth. It does not establish production interoperability,
population-level performance, external label independence, legal validity,
prevalence of any failure mode in deployed systems, or cryptographic
verification in the state, authority and binding stages
(`attestation_result` objects, `issuer_signature_valid` /
`native_evidence_valid` / `protocol_valid`, and every subject string the
binding stage compares are corpus-supplied; structural appraisal and string
agreement are not attestation). The 8 cross-layer denials show that the
seam is now *representable and exercised*; they say nothing about how often
such transactions occur anywhere. These disclaimers are embedded in
`corpus.json`, `results/summary.json` and `results-sql-oracle/summary.json`,
not only in this README.
